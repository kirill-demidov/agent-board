# Warp: открывать сессии вкладкой, а не окном

Статус: **DONE** (2026-08-06)
Область: `agentboard.py`, `README.md`, `CLAUDE.md`

## Задача

По клику на карточку при `AGENTBOARD_TERMINAL=Warp` каждый раз рождалось новое
окно Warp. Нужно: вкладка в текущем окне.

## Что мешало

- `_open_in_warp` шёл через launch configuration (`~/.warp/launch_configurations/*.yaml`
  + `warp://launch/<name>`). У конфига верхний ключ — `windows:`; вкладку в уже
  открытом окне им не сделать, Warp всегда открывает окно.
- Настройки «новые окна как вкладки» у Warp нет. В `defaults read dev.warp.Warp-Stable`
  из оконного только `UseVerticalTabs`. Нативные macOS-табы Warp не использует,
  поэтому системный «Prefer tabs when opening documents» тоже не при делах.
- URI `warp://action/new_tab?path=<dir>` открывает вкладку в текущем окне, но
  параметра для команды у него нет.

## Решение

Команду передаём вкладке через файл, забирает её сам шелл вкладки.

1. `WARP_ATTACH_FILE = /tmp/agentboard-<uid>-warp-attach` — доска пишет туда
   готовую строку `tmux attach -t <session>` (0600).
2. `warp://action/new_tab?path=<cwd>` + `osascript … activate` — вкладка в
   текущем окне, в папке сессии.
3. Снипет `WARP_ZSHRC` в `~/.zshrc` (метки `# >>> agentboard: Warp tabs >>>`):
   читает файл, удаляет его и `exec`-ает команду.

Три предохранителя в снипете, чтобы случайная вкладка не улетала в чужую сессию:
`$TERM_PROGRAM == WarpTerminal`, `-z $TMUX`, возраст файла < 30 c. Файл
удаляется до проверки возраста — просроченный не переживёт первую же вкладку.
На старте сервера висячий файл от прошлого запуска тоже удаляется.

## Установка снипета

- Плашка «включить хуки» (`/api/hooks_install` → `install_hooks`) ставит снипет,
  когда `TERMINAL_APP == "Warp"`.
- Кому плашка уже не показывается (хуки стоят), снипет доставляет сам
  `_open_in_warp` при первом открытии — но только если `hooks_state()` уже не
  пустой, то есть конфиги доске уже доверены. Новая вкладка читает свежий
  `~/.zshrc`, поэтому вкладкой идёт уже этот клик.
- Перед первой правкой `~/.zshrc` кладётся `~/.zshrc.agentboard-bak`,
  повторная установка блок не дублирует (замена по меткам).

## Отвергнутые варианты

- **Keystroke через System Events** (`cmd+T` + набор команды): нужен
  Accessibility для процесса доски, ломается на раскладке и потере фокуса,
  первый символ съедают rc-хуки промпта (та же болячка, из-за которой Terminal
  получает `.command`-файл, а не `do script`).
- **Launch configuration с одной вкладкой**: `windows:` — обязательный
  верхний уровень, окно всё равно новое.

## Фолбэк

Нет снипета (или нет согласия на правку конфигов) — прежнее поведение:
launch configuration и новое окно. Поведение не сломано ни для кого.

## Проверено

- `zsh -n` на снипете; прогон `zsh -i` c подменой `exec` на `echo`: срабатывает,
  файл удаляет.
- Предохранители: `touch -t 202601010000` (просрочен) и `TERM_PROGRAM=Apple_Terminal`
  — не срабатывает.
- `_install_warp_zshrc` идемпотентен, бэкап создаётся.
- `_open_in_warp` с подменённым `subprocess.run`: вызывает
  `open warp://action/new_tab?path=<cwd>` и пишет верную attach-строку.
- Не проверено вживую: сам клик по карточке в GUI Warp — за пользователем.
